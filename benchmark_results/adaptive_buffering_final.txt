=============================================================================
ARCHITECTURE
=============================================================================

Three-tier adaptive buffering:
- Small (512B): Default, optimized for low latency
- Medium (4KB): Auto-upgrade when ≥2 commands detected
- Large (16KB): Auto-upgrade when ≥8 commands detected
- Downgrade: 2-second idle timeout → revert to Small

Conditional read-ahead:
- Disabled for Small tier (preserves latency)
- Enabled for Medium/Large tiers (reduces syscalls)

=============================================================================
KEY INSIGHTS
=============================================================================

1. MikkaDB matches Redis at P=1 (109K ops/sec) with better latency
2. Redis dominates deep pipelining (2-3x faster at P=10/100)
3. Adaptive buffering scales 5x better than baseline (528K vs 64K plateau)
4. Read-heavy workloads show 2-4x better performance than write-heavy

Production use cases:
- MikkaDB: Low-latency real-time apps, write-heavy workloads, single requests
- Redis: Batch processing, deep pipelining, maximum throughput scenarios
