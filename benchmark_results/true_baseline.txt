Key Observations:
-----------------
1. P=1 performance (33.8k ops/sec) is MUCH LOWER than local testing (110k)
   - This is expected: remote server has network latency + different CPU
   - Remote server is the TRUE production-like baseline

2. P=10 shows modest improvement (42% gain over P=1)
   - Buffering helps with batched requests
   - Latency increases proportionally to pipeline depth

3. P=100 shows REGRESSION (-8.6% vs P=10)
   - Likely head-of-line blocking or connection saturation
   - Baseline architecture not optimized for high-throughput pipelining

4. Comparison to phase1_baseline_pipelining.txt (LOCAL):
   - Local P=1: 110,725 ops/sec vs Remote P=1: 33,815 ops/sec
   - 3.3x difference due to network latency and CPU differences
   - ALL remote benchmarks should be compared to THIS baseline, not local

Next Steps:
-----------
1. This establishes the TRUE starting point for remote optimization work
2. Any pipelining/buffering optimizations should be measured against:
   - P=1 target: maintain or improve 33.8k ops/sec
   - P=10 target: improve beyond 48.2k ops/sec
   - P=100 target: improve beyond 44.0k ops/sec (currently regressing)

3. Expected gains from pipelining optimization:
   - Moderate: 15-25% improvement (50-60k ops/sec at P=10)
   - Best case: 40-50% improvement (60-70k ops/sec at P=10)

Deployment Note:
----------------
This baseline uses the Actor model architecture with no buffering optimizations.
The code at commit 692a4c0 represents the foundation before any I/O or
concurrency optimizations were attempted.
